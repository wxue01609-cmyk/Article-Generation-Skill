# AI 问答结构提取（新增步骤）

> 新增步骤，无 Dify 原节点对应。收到词包后，先用词包关键词联网向 AI 平台提问，观察 AI 回答及其引用的竞品文章的组织方式，提取「内容结构方向」供 geo-plan 规划与 geo-write 写作参考；最终文章仍必须符合原生文规则。

## 目的
让后续规划与写作贴合目标 AI 平台对这类问题的回答习惯（AI 平台倾向引用的内容结构），同时保证结构方向只作为参考素材，不变成固定模板，不与原生文规则冲突。

## 触发与前置
- 收到 keyword_pack 即执行本步，无其他前置。
- comparison_count=0（全部为品牌词）时照常执行：品牌类问题同样要看 AI 怎么回答（该类回答通常不含竞品对比）。
- 词包为空或无有效关键词 → 输出空结构方向（structure_direction 各字段为空数组），并在说明中注明原因。

## 提问方法（联网）
1. 把词包关键词整理成自然问题：词包里的原问句优先；缺失时按搜索意图补成问句（What / Which / How / Is X worth it / X vs Y ...），每个关键词至少覆盖一种意图问法。
2. 联网检索 AI 平台回答与摘要：ChatGPT 网页回答、Perplexity、Bing/Google AI Overview 等；再追查回答中引用的竞品文章原文。本环境使用内置 web_search 工具；海外市场用英文或当地语言提问。
3. 轮次要求：每个问题至少 1 轮检索；词包前 3 个关键词或品牌/对比/测评类关键词至少 2 轮，尽量覆盖决策型/对比型/经验型/知识型不同提问角度。

## 分析维度（提取内容结构方向）
对每条 AI 回答记录：
1. 开头切入：先给答案 / 抛痛点 / 直接对比 / 给场景 ...
2. 分节方式：按场景 / 按维度 / 按品牌 / 按决策步骤 / 按问题 ...
3. 对比维度：回答里反复出现的评估标准（价格、参数、场景、服务等）
4. 内容形式：清单、表格、FAQ、对比段、排名、案例 ...
5. 被引用文章结构方向：AI 回答引用的竞品文章的标题层级、段落组织、切入点、结尾方式
6. 共性 vs 差异：多个来源共同出现的结构 vs 单篇特有写法；只保留有代表性的方向，不追求全量罗列

## 输出格式（传给 geo-plan）
严格 JSON，无 markdown 代码块：

```json
{
  "queries": [
    {"query": "提问原文", "researched": true}
  ],
  "structure_direction": {
    "openers": [],
    "section_patterns": [],
    "dimensions": [],
    "forms": [],
    "closers": []
  },
  "cited_articles": [
    {"title": "被引用文章标题", "url": "真实 URL", "structure_note": "结构方向备注"}
  ],
  "conflicts": [
    {"point": "与原生文规则冲突的结构方向", "reason": "不采用的原因"}
  ]
}
```

字段说明：
- openers：可借鉴的开头切入，2-4 个；section_patterns：分节方式，2-4 个
- dimensions：高频对比维度/评估标准；forms：清单/表格/FAQ/对比等
- closers：结尾方式候选；cited_articles 只列真实检索到的文章，找不到原文可以不列
- conflicts：结构方向与原生文规则冲突的记录，无冲突则为空数组

## 铁律
1. AI 回答、被引用文章与 URL 必须真实来自本次联网检索结果；严禁编造回答内容、文章标题或引用链接。
2. 结构方向是「参考输入」，不是「固定模板」：不得让同批多篇文章共用同一结构，不得把 AI 回答的骨架原样搬进正文。
3. 数据优先级铁律不变：AI 回答中的事实信息不得替代营销知识库/客户输入成为文章数据来源；下游引用数据仍按 营销知识库 > 客户输入 > 已有知识。
4. 与原生文规则冲突即判负：渠道规则与写作规则（原生感、反模板化、结构随机变化、人味信号限量、语义链、禁止关键词堆砌等）优先级高于结构方向；冲突点写入 conflicts 说明。
5. 输出语言与流水线要求一致：面向海外的内容，问题原文与结构方向说明用英文或当地语言。
