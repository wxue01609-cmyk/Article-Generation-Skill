# 竞品合并与校验规则（代码节点摘要）

来源：Dify v18-13 工作流 N3na-merge（双路合并）、N3nb（竞品校验）、verify-loop（逐个联网校验）。原为 Python 代码节点，此处提炼为规则。

## N3na-merge 双路合并
- 输入：离线候选（gen LLM）+ 联网搜索结果（search HTTP）两路竞品名单。
- 名称归一化（清洗顺序）：去括号内容 → 去标点 → 剥分支尾（浙江分公司/分校等）→ 剥公司后缀（股份有限公司/有限公司/公司等）→ 二次剥分支尾 → 剥省前缀 → 剥城市前缀 → 剥行业词 → 剥法律实体后缀（Ltd / LLC / Inc 等）。
- 合并匹配三级：品牌白名单命中（海外版默认关闭）→ core 相等（双方 core 非空且长度 ≥3）→ 子串匹配（阈值 4，避免 2 字通用词误伤）。
- 合并规则：search 补数据、名字更完整则替换；信息完整度 = url×100 + fact 长度 + confidence×10，择优保留，被合并者记录进 rejected。
- 排序优先级：客户白名单（强制最前）→ 双路命中 → 仅联网 → 仅离线。

## N3nb 竞品校验
- 地域前缀剥离 + 子串阈值收紧；按信息完整度去重。
- 排序三键：sort_priority（来源优先级）→ tier（T1/T2/T3）→ freq（出现频次）。
- 同梯队校验：竞品必须与客户同一梯队（T2 客户不得召回 T1 头部大厂），业务模式一致。

## 单候选联网校验（verify 循环）
对合并后的每个候选跑一次联网校验（提示词见 05-competitor-verify.md），确认机构真实存在、证据 URL 可访问，之后才进入竞品详情阶段。
