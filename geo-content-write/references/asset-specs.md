# 各资产成稿模板（成稿阶段）

## 全局交付形态（最高优先级）
- 每个资产输出一个**完整可发布 HTML 页面**，不是 Markdown，也不是 Markdown 代码块。
- 必须包含：`<!doctype html>`、`<html>`、`<head>`（charset/viewport/title/内联 `<style>`）、`<body>`。
- 样式全部写在 `<style>` 中，禁止外链 CSS/JS/字体/图片；页面在 360px–1440px 宽度可读。
- 正文用语义化标签；表格用 `<table>`；CTA 用带背景色的链接/按钮；不要残留 `**`、`##`、`| --- |` 等 Markdown 标记。
- 可另存同名 `.md` 作为内部底稿，但交付物只认 `.html`。

## blog · 官网博客
- 文件：`assets/blog/<id>.html`
- 结构：唯一 H1 → 直接结论段（≤120 词，2-3 句答案）→ 4-7 个 H2（判断标准/参数/场景/边界，每节一个可核验论点）→ FAQ（原问句 3-5 条）→ 结论（一句话 + 软 CTA）
- 字数：700-1500 词
- 禁：竞品名、TL;DR（整批最多 1 篇）、作者署名

## landing · 官网落地页
- 文件：`assets/landing/<id>.html`
- 结构：Hero（H1 ≤60 字符、副标题、证据条、主 CTA 按钮）→ 痛点 → 解决方案 → 3 个收益模块 → 工作方式 → 规格/证据 → 使用场景 → 异议处理 → FAQ（3-5）→ 结尾 CTA
- 字数：300-700 词；单一转化目标；CTA 按钮文案 = brief.cta
- HTML 需含 header/hero/section/footer 结构与左右留白样式

## sku · 官网产品/SKU 页
- 文件：`assets/sku/<id>.html`
- 结构：H1（品牌+型号+规格+场景）→ 5 条卖点（每条“利益 + 证据”）→ 3 段描述 → 参数表（Markdown 表格，口径来自知识库，待核验标注）→ 包装内容 → 兼容性 → 适用/不适用 → FAQ 3-5 → Product schema（HTML 场景可选）
- 字数：150-400 词

## category · 官网类目页
- 文件：`assets/category/<id>.html`
- 结构：类目导语 → 选购维度（判断标准）→ 子类目分块（3-6，每个带适用边界）→ 自家产品对比表（只列自家型号）→ 场景建议 → FAQ（原问句）→ 内链
- 字数：600-1000 词

## thirdparty_pr · 三方新闻稿
- 文件：`assets/thirdparty_pr/<id>.html`
- 结构：标题（品牌+新闻点）→ 5W 导语一段 → 3 个事实点（每点 2-3 句 + 一句官方引语）→ 行业意义 → Boilerplate（品牌一句话 + 官网 + 联系方式占位）
- 字数：400-700 词；不写促销码；不点竞品名

## thirdparty_review · 三方评测/对比
- 文件：`assets/thirdparty_review/<id>.html`
- 结构：披露声明（与品牌关系）→ 评估方法 → 各维度对比表（数据有出处）→ 分场景结论（适合谁/不适合谁）→ 局限性 → FAQ
- 字数：700-1200 词；结论必须“需求→方案”，不写成广告

## qna · 社区问答
- 文件：`assets/qna/<id>.html`
- 结构：问题式标题 → 真实场景+约束（具体、有上下文）→ 已尝试/已了解 → 2-5 个判断问题 → 结尾邀请经验
- 字数：150-350 词；0 链接、0 表格、0 小标题、0 促销；口语化，保留 2-3 处不确定表达；可提及品牌身份（如“I work at X”）

## social · 社交帖
- 文件：`assets/social/<id>.html`
- 结构：钩子（1 句）→ 2-3 个要点 → 结尾问题/CTA → 3-5 个话题标签
- 字数：≤150 词；平台规则优先（X/LinkedIn/Facebook 差异默认由动作说明）

## ecommerce · 电商 Listing
- 文件：`assets/ecommerce/<id>.html`
- 结构：标题（≤200 字符）→ 5 条 bullet（利益+参数，每条 ≤80 字符）→ 描述（3 段）→ 后台关键词（不堆砌）→ A+ 模块脚本（文本版）→ 图片/视频脚本说明
- 字数：200-500 词；合规声明（如安全/认证）

## faq · 帮助中心/FAQ
- 文件：`assets/faq/<id>.html`
- 结构：5-8 个原问句 → 每个：直答 40-60 词 → 步骤/边界 → 相关链接
- 字数：300-600 词；schema FAQPage 可选（HTML 场景）

## 通用
- 全部正文语言 = `article_language`（缺省英文）；禁止中文正文。
- 官网类不出现竞品品牌名；绝对化词禁用；参数口径与知识库一致。
- 每个资产以 `<!-- asset: <asset_id> -->` 开头便于核对。

## target_url 与内链
- 官网资产：落地 URL 用 Brief 的 `target_url` 相对路径；`site_inventory` 已有时直接复用，不新增路径。
- 三方资产：不生成站内 URL；`target_url` 为 `external:TBD` 时不写链接，只给发布平台说明。
- 用户填写了「待改造商品页 URL」（fields.source_urls）且 Brief 的 `internal_links` 里有该商品页完整 URL 时：若本资产内容与该商品相关，把链接**自然写进正文**（产品介绍或购买建议段落的锚文本），不要做成文末孤立的“参考资源”列表；社区问答（community）保持 0 链接。
- 所有链接只使用可核验真实来源；无法核验一律不插链接。
- 发布提示：`target_url` 为站内相对路径（`/` 开头）的资产，在 `<body>` 开头插入中文高亮提示（`<!-- GEO-PUBLISH-NOTE -->` 标记），写明「需发布到官网路径 <target_url>，否则被引用为内链时会失效，发布前删除本提示」；`target_url` 为空时用红色提示要求先补路径；完整 `http(s)` URL 与 `external:TBD` 不加提示。提示文案为中文、属于运营标注，不受「正文必须英文」限制。
